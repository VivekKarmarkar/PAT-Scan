# `reproduce-page-basic` — NOTES.md

> Serialized judgment calls from reproducing Wei et al. (Appl. Math. Modelling 134, 2024) pages 1–9.
> Will be extended through page 11 before the skill is built.
> Purpose: capture the micro-decisions that don't live in the pipeline itself, so the skill can make them consistently on unseen pages.

---

## 1. The pipeline (fixed)

For each page N:

```bash
# Step 1: extract prose (deterministic text layer)
pdftotext -f N -l N <paper>.pdf <scratch>/wei_pageN_raw.txt

# Step 2: read rendered page for equations + figure layout
#         (Read tool, pages N-N) — hand-transcribe equations from the visual

# Step 3: write wei_pageN.tex combining
#         - prose from pdftotext (soft hyphens cleaned, line breaks re-flowed)
#         - equations from visual transcription
#         - figure placeholders for any figures on the page
#         - section/subsection headers as seen in the visual

# Step 4: compile
cd <out_dir>
pdflatex -interaction=nonstopmode wei_pageN.tex

# Step 5: open for review
xdg-open wei_pageN.pdf
```

**Why hybrid**: `pdftotext` is character-deterministic on prose (it reads the PDF text layer directly, no inference) but mangles equations into scattered line fragments. The visual Read tool sees equations cleanly but would hallucinate if asked to re-transcribe long prose from memory. Each tool is used only where it's reliable.

### 2a. Footer convention: `<ORIG_PAGE> → <SUB_PAGE>` (new, page 10 onwards)

**Problem**: each reconstructed `.tex` file compiles to 2 physical PDF pages (standard `article` class is less dense than Elsevier's 2-column house style, so a single journal page's content overflows onto a second page). The old convention `\setcounter{page}{135}` with `\cfoot{\small \thepage}` caused both physical pages to appear to be "page 135" from the reader's perspective — the first page would show "135" in the footer and the second page would show "136", which is misleading (the second page isn't page 136 of the journal, it's the overflow of page 135's content).

**New convention**: hardcode the original journal page number into `\cfoot`, and use the LaTeX page counter for the sub-page index. Example for Wei page 135:

```latex
\cfoot{\small 135 $\to$ \arabic{page}}
\setcounter{page}{1}
```

This makes the footer on the first physical page say "135 → 1" and the footer on the second physical page say "135 → 2". The reader immediately understands: "this is part 1 of the reconstruction of journal page 135." No ambiguity.

**Why hardcode, not redefine `\thepage`**: `\thepage` is used by LaTeX internally for cross-references, table of contents, PDF bookmarks, and hyperlink targets. Redefining it to contain a string like `"135 $\to$ 1"` has subtle side effects on these other systems. Hardcoding the format inside `\cfoot` is side-effect-free: the LaTeX page counter sees a normal integer, but the footer displays the format we want.

**Semantic shift**: under the new convention, `\arabic{page}` is the *reconstruction sub-page counter*, not the *journal page number*. If you need the journal page number elsewhere in the document (e.g., for a `\ref{}` to a label), you'd need to track it separately. For a single-page reconstruction document this doesn't come up, so the shift is cost-free.

**Pages 1–9 status**: the originals (`wei_page1.tex` … `wei_page9.tex`) use the old convention and are NOT modified — per the "don't touch what works" rule. Alongside them, a parallel set of files `wei_page1_updated.tex` … `wei_page9_updated.tex` was generated by the helper script `_rebuild_updated_pages.py`, applying the two mechanical substitutions documented above. Both sets now coexist in `wei_reconstruction/`:

- `wei_pageN.tex` / `wei_pageN.pdf` → old footer convention, untouched
- `wei_pageN_updated.tex` / `wei_pageN_updated.pdf` → new footer convention, auto-generated

Page 10 onwards uses the new convention directly (no `_updated` suffix, since there's no "original" to preserve).

**The `_updated` files are throw-away if we later decide to commit fully to the new convention** — they're the "temporary alternative" that coexists with the originals until consistency matters more than preservation. When the skill is eventually built, the decision about which set to copy into `examples/` can be made then. Until then, both exist.

**Helper script**: `wei_reconstruction/_rebuild_updated_pages.py` — idempotent, run with `python3 _rebuild_updated_pages.py` from the reconstruction directory. Overwrites `wei_pageN_updated.tex` for N in 1..9 without touching the originals. Uses `assert` to fail loudly if the expected old strings aren't found in the source.

## 3. Document-level conventions for the Wei paper

- **Running header**: `Y.~Mei et al.` on left, full journal/volume/page on right. Page number centered at footer.
- **Page counter**: set via `\setcounter{page}{N}` at the top of each page's `.tex`. Journal page numbers for Wei are 126 (page 1) through 147 (page 22).
- **Equation counter**: set via `\setcounter{equation}{M}` where M is the last equation from the previous page. So each page starts with the next equation number relative to the paper, not relative to the document.
- **Citation format**: literal `[12]`, `[20--23]`, `[13,14]` as text markers, NOT `\cite{}` commands. There is no bibliography in these per-page reconstructions.
- **En-dashes in citation ranges**: use LaTeX `--` (two ASCII hyphens), not Unicode `–`.
- **Section headers**: `\section*{Methods}`, `\section*{Results}` (unnumbered).
- **Subsection headers (italic)**: `\subsection*{\textit{Forward problem}}`, `\subsection*{\textit{Gradient computation}}`, `\subsection*{\textit{Inverse problem}}`, `\subsection*{\textit{Case 1: A layered rectangular structure}}`. Wei italicizes subsections; reproduce the italic.

## 5. Known typesetting anomalies in the source

Preserve these *verbatim* as reproduction fidelity, not as corrections:

1. **Eq. (12) on page 4 is rendered in bold typeface in the original.** Both the Greek letters (μ, φ) and Roman letters (x, H) are bold. Every other equation in the paper uses regular weight. This is almost certainly a typesetting error in the Elsevier production process (a stray `\boldmath` that wasn't closed), but the paper is what it is. Reproduced with `\boldsymbol{\mu}`, `\boldsymbol{\phi}`, `\mathbf{H}`, `\mathbf{x}`. Do not "fix" it.

2. **"1.0mm*0.2 mm" in page 8 prose** — the asterisk is a multiplication sign that pdftotext rendered as literal `*`. Reproduced as `1.0\,mm $\times$ 0.2\,mm` for readability, but the ASCII `*` is what pdftotext actually returns.

3. **"0.2 %" and "40 %" and "5 %" all have a space before %** — that's Elsevier house style. Reproduced as `0.2\,\%` etc. (thin space + escaped percent).

4. **Cut-off sentences at page breaks** — most pages end mid-sentence, continuing on the next page. Preserve the cut-off; do NOT try to complete the sentence from context. The next page's reconstruction will pick up where it left off.

## 6. Prose cleanup rules (mechanical, deterministic)

1. **Soft hyphens** (`­`, U+00AD): join the two halves into one word.
   - `distri­bution` → `distribution`
   - `im­plicit` → `implicit`
   - `compo­nents` → `components`
   - `minimi­zation` → `minimization`
   - `simu­lation` → `simulation`

2. **Line breaks inside paragraphs**: collapse to spaces. The `.tex` file should have one paragraph per LaTeX paragraph (separated by blank lines), not one line per visual line from pdftotext.

3. **Unicode en-dash `–`** (U+2013) in citation ranges: convert to LaTeX `--`.

4. **Unicode right single quotation mark `'`** (U+2019) in contractions like "it's": convert to ASCII `'` for safety.

5. **LaTeX special characters**: escape `%`, `&`, `$`, `_`, `#` when they appear in prose text. Note: `_` and `$` inside math mode are fine.

6. **Stray scattered-equation fragments**: pdftotext spreads equation characters across many lines (see Eq. 6 and Eq. 7 on page 3, or all of page 7). These are NOT prose. Delete them entirely from the pdftotext output when building the .tex file; the equations come from the visual Read step.

## 7. Figure placeholder format (standard template)

All figure placeholders use this structure:

```latex
\vspace{1em}
\begin{center}
\fbox{\parbox{0.92\textwidth}{\centering\vspace{1em}
\textbf{[Figure N — placeholder]}\\[0.8em]
<description of what the figure shows>
\vspace{1em}}}
\end{center}
\vspace{0.3em}
\begin{center}
\textbf{Fig. N.} <caption verbatim from paper>
\end{center}
```

**Description should include:**
- Brief visual description (colors, layout, subpanels)
- Key labels visible in the figure (control points, axis values, colorbar range)
- Structural meaning (what the figure is illustrating about the math)

**Do NOT:**
- Try to reproduce the figure graphically
- Invent details not visible in the rendered page image
- Use `\includegraphics` (there's no image file to include)

**Figure types encountered so far:**
- B-spline control-polygon diagrams (page 3)
- Bilayer shear modulus field (page 4)
- Inclusion-embedded shear modulus field (page 5)
- Heaviside approximation plot (page 5)
- Optimization flowchart (page 6)
- Target shear modulus distributions (page 8)
- Optimization trajectory sequence (page 9, Fig. 7)
- Explicit-vs-Implicit side-by-side comparison (page 9, Fig. 8)

**Figure types still to come** (per Vivek): more result figures + at least one table (page 11).

## 7a. Table convention (introduced page 11)

Wei's Table 1 is a 2-level column header (method → number of datasets) with a 2-level row structure (noise level → sample). The reproduction uses `booktabs` for the three-rule structure (`\toprule`, `\midrule`, `\bottomrule`) the paper uses, and `\cmidrule` for the partial horizontal rules under the method-level column headers. Row grouping by noise level uses `\multirow` from the `multirow` package.

**Packages added to the stable preamble for pages with tables**:
```latex
\usepackage{booktabs}   % \toprule, \midrule, \bottomrule, \cmidrule
\usepackage{multirow}   % \multirow for grouping row-header cells
\usepackage{array}      % extended column specs (defensive — harmless if unused)
```

**Table caption convention**: Wei places the table number+title *above* the table, not below (journal house style). The reproduction matches this:
```latex
\noindent\textbf{Table N}\\[0.2em]
{\small <caption text — one sentence, no full stop typically>}
\vspace{0.3em}

\begin{center}
\small
\begin{tabular}{...}
...
\end{tabular}
\end{center}
```

**Cell content fidelity**:
- Percent values: preserve exactly as printed (`0.04\,\%`, `0.003\,\%`), with the Elsevier thin-space-before-`%` convention.
- Repeated leading zero (e.g., `0.00 %`) is kept — do NOT compress to `0 %`.
- Column alignment: numeric cells are visually left-aligned in the original (not decimal-aligned), so use `c` column specs.

**What to watch for on unseen pages**: if a new table uses `\multicolumn` headers with more than 2 group levels, or merges cells diagonally, the template above will need to be extended. The skill should fall back to "transcribe the visible structure literally" rather than trying to be clever.

## 10. Scope boundary (what `reproduce-page-basic` does NOT do)

- Does NOT extract figures as images
- Does NOT redraw figures as TikZ
- Does NOT reproduce pixel-perfect Elsevier layout (uses standard article class)
- Does NOT build a BibTeX bibliography (citations are literal `[N]` markers)
- Does NOT handle scanned PDFs without a text layer (pdftotext requires embedded text)
- Does NOT resolve mathematical ambiguity automatically (when visual reading is ambiguous, the LLM step has to choose)

These are the categorical limitations. Future `reproduce-page-with-figures` or `reproduce-page-full` skills would address them one at a time.
